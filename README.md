# README_FOR_AI — Разряд-Арена Bot

## 1. Назначение проекта
**Разряд-Арена** — Telegram-бот для организации любительских турниров и команд по нескольким видам спорта.

Бот закрывает полный рабочий контур проекта:
- регистрация и профиль пользователей
- создание и управление командами
- набор игроков
- подача заявок в турниры
- турнирные invite-ссылки
- реферальная система по видам спорта
- генерация и просмотр сеток
- назначение матчей
- CS2 map veto / pick-ban
- ручной ввод результатов и статистики
- история матчей и персональная статистика
- рейтинг команд
- рейтинг игроков и live-посты рейтинга в канале
- админ-панель и модерация
- рассылки пользователям
- экспорт данных для статического сайта проекта

Поддерживаемые виды спорта в текущей версии:
- CS2
- Футбол
- Баскетбол
- Волейбол

## 6. Middleware

### `BanCheckMiddleware`
Проверяет:
- забанен ли пользователь
- если да, блокирует доступ ко всем обычным действиям

Исключение:
- администратор не блокируется этой веткой

### `RequiredSubscriptionMiddleware`
Проверяет:
- подписан ли пользователь на обязательный канал

Если нет:
- основные сценарии бота не выполняются
- пользователю показывается клавиатура с подпиской и проверкой

Отдельно пропускается:
- callback `check_subscription`

### 7.2.1 Реферальная система
Файлы:
- `handlers/referrals.py`
- `utils/referral_service.py`

Что умеет пользователь:
- открыть раздел `🎁 Реферальная система`
- создать несколько ссылок под нужные виды спорта
- задать имя / метку ссылки
- посмотреть карточку ссылки и её статистику
- отключить ссылку

Как работает атрибуция:
- засчитывается только для нового пользователя
- побеждает первая открытая реферальная ссылка
- self-referral запрещён
- уже существующий пользователь не перепривязывается

Как начисляются бонусы:
- владельцу ссылки `+2`, когда реферал попадает в одобренную заявку турнира по тому же спорту
- владельцу ссылки `+3`, когда реферал сыграл первый нетехнический матч
- самому рефералу `+2` за первый нетехнический матч

Куда идут очки:
- в общий рейтинг спорта
- в текущий сезонный общий рейтинг спорта
- форматный рейтинг CS2 рефералка не меняет

### 7.4 Турниры
Файл:
- `handlers/tournaments.py`

Что умеет пользователь:
- открыть раздел турниров
- выбрать вид спорта
- посмотреть список турниров по спорту
- открыть карточку турнира
- посмотреть список одобренных команд турнира
- подать заявку своей командой
- открыть турнирную сетку, если она уже сгенерирована
- открыть «📋 Очередь матчей» для турниров в режиме sequential

#### Режимы расписания турнира
- **fixed (обычный)** — текущее поведение. У каждого матча своё время и место, назначаются администратором. За 1 час до матча — напоминание. CS2 veto стартует по времени матча.
- **sequential (последовательный, живая очередь)** — единое время старта турнира, общая локация. Матчи играются строго по одному. Когда текущая пара завершила матч — автоматически активируется следующая. Команды получают:
  - после генерации сетки — уведомление о сопернике (если уже определён)
  - за 1 час до старта турнира — общий broadcast
  - в момент старта — персональное сообщение со своей позицией в очереди
  - когда соперник определяется по итогам предыдущего раунда — отдельный push
  - авто-обновляемое queue-сообщение со статусом очереди
- Режим выбирается при создании турнира; в редактировании можно сменить его до генерации сетки и до фактического старта.
- Особенности sequential-режима:
  - Матч за 3-е место играется **перед финалом** (порядок очереди: …полуфиналы → матч за 3-е место → финал).
  - В уведомлении «⚔️ Назначен матч» строки `🕒 Время начала турнира` и `⏳ Перед вами: N пар` выводятся только для матчей первого раунда. Для матчей дальше первого раунда и матча за 3-е место они не показываются — турнир уже идёт, а актуальная позиция в очереди видна в queue-сообщении.
  - Заголовок уведомления о матче за 3-е место — `🥉 Назначен матч за 3-е место`.
  - Команда, которая проиграла полуфинал, в queue-сообщении видит «🥉 Вы ждёте матч за 3-е место» с указанием второго полуфинала, по итогу которого появится её соперник, — даже если сам матч за 3-е место ещё не создан в БД.
  - После завершения каждого матча queue-сообщение пересылается заново тем командам, у кого изменилось важное состояние (новый этап, появился соперник, стали активными, завершили турнир) — старое сообщение удаляется, новое присылается в конец чата, чтобы не пряталось за CS2 pick/ban.

Файлы режима sequential:
- `utils/sequential_tournament.py` — ядро (очередь, уведомления, lifecycle)
- `_match_due` в `utils/veto_service.py` — для sequential гейт = `queue_state='active'`

Что показывает карточка турнира:
- название
- вид спорта
- требуемый размер команды
- город
- даты регистрации и даты проведения
- лимит команд
- возрастные ограничения
- статус
- invite-ссылка
- описание турнира, если заполнено

#### Проверки перед подачей заявки
При подаче заявки бот проверяет:
- существует ли турнир
- открыт ли этап регистрации
- существует ли команда
- совпадает ли вид спорта команды и турнира
- является ли пользователь капитаном этой команды
- не занят ли лимит команд
- нет ли конфликта по участникам
- нет ли уже активной заявки этой команды
- можно ли подать повторную заявку после отклонения

#### Конфликты по составу
Если участник команды уже заявлен в этом турнире за другую команду:
- бот блокирует подачу
- показывает подробный список конфликтующих игроков и их статус

#### Статусы заявок
- `pending`
- `approved`
- `rejected`
- `excluded`

#### Даты турнира
Для новых турниров разделены:
- даты регистрации
- даты проведения

Логика показа:
- во время регистрации бот показывает и регистрацию, и проведение
- после старта турнира показывает только проведение
- если даты проведения не указаны, выводится `будут объявлены позже`

### 7.5 Сетка турнира и матчи
Основные файлы:
- `handlers/brackets.py`
- `utils/bracket_utils.py`
- `utils/bracket_visualizer.py`
- `tournament_bracket.py`

Что реализовано:
- генерация сетки
- перегенерация сетки
- просмотр сетки пользователем
- просмотр отдельного матча в сетке
- назначение времени и места матча
- редактирование времени и места
- ручной ввод результата
- продвижение победителя по сетке
- автоматическая обработка BYE-сценариев
- создание матча за 3-е место
- автоматическое создание матча за 3-е место, когда это уместно
- корректные подписи этапов основной сетки до 64 команд

#### Просмотр сетки
Бот показывает:
- список матчей по раундам
- статус заполнения времени и места
- победителя матча, если он уже определён

#### Планирование матчей
Есть мастер назначения матчей:
- бот находит готовые, но не назначенные матчи
- запрашивает дату и время
- запрашивает место
- сохраняет в БД
- при необходимости сразу отправляет уведомления участникам

#### Матч за 3-е место
Поддерживается:
- ручное создание через подтверждение
- автоматическое создание после нужных полуфиналов

#### Этапы сетки
Сетка и карточки матчей используют единые названия этапов:
- `Финал`
- `Полуфинал`
- `1/4 финала`
- `1/8 финала`
- `1/16 финала`
- `1/32 финала`

Матч за 3-е место обрабатывается отдельно от основной сетки.

- для CS2 форматный выбор вынесен отдельно и не показывается как обязательный шаг
- если данных нет, бот показывает, что рейтинг пока пуст
- live-посты рейтинга в канале могут автоматически обновляться после изменений

## 8. Админский функционал
Основной файл:
- `handlers/admin.py`

Это самый большой сценарный блок проекта.

### 8.1 Общая админ-панель
Администратор может:
- открыть панель через `/admin`
- перейти к управлению пользователями
- перейти к турнирам
- перейти к заявкам
- перейти к рейтингам
- перейти к командам
- создать матч вручную
- сделать рассылку

---

### 8.2 Управление турнирами
Что умеет администратор:
- создать турнир
- посмотреть список турниров с пагинацией
- открыть карточку управления турниром
- редактировать поля турнира
- изменить вид спорта
- удалить турнир
- завершить турнир

При создании турнира заполняются:
- название
- вид спорта
- город
- дата начала регистрации
- дата окончания регистрации
- дата начала проведения
- дата окончания проведения
- лимит команд
- требуемый размер команды
- минимальный возраст
- максимальный возраст
- описание

#### Карточка управления турниром
Содержит:
- полную информацию по турниру
- invite-ссылку
- управление сеткой
- управление командами и заявками
- управление персональными турнирными уведомлениями
- панель CS2 veto
- панель MVP
- редактирование
- удаление
- завершение

#### Завершение турнира
При завершении используется логика:
- определения 1, 2 и 3 места
- завершения турнира
- распределения наградных мест

---

### 8.3 Турнирные invite-ссылки
Администратор может:
- открыть меню invite-ссылки турнира
- показать ссылку
- обновить токен

Ссылка строится автоматически по username текущего бота:
- `https://t.me/<bot_username>?start=tournament_invite_<token>`

---

### 8.4 Модерация заявок и составов турнира
Что умеет администратор:
- смотреть список всех pending-заявок
- открывать карточку команды-заявителя
- одобрять заявку
- отклонять заявку
- исключать команду из турнира
- разрешать повторную подачу после исключения
- просматривать команды турнира по секциям:
  - approved
  - pending
  - excluded
  - rejected

В карточке команды администратор видит:
- состав
- капитана
- данные команды
- соответствие требованиям турнира

Дополнительно:
- после окончания регистрации ответственным и администраторам могут приходить tracked-уведомления о том, что пора начинать турнир
- после одобрения заявки может автоматически сработать реферальное начисление владельцу ссылки

---

### 8.5 Генерация и управление сеткой
Администратор может:
- сгенерировать сетку турнира
- перегенерировать сетку
- открыть сетку турнира
- назначить время и место матчей
- редактировать назначение
- создать матч за 3-е место
- в CS2 запускать и контролировать map veto / pick-ban

После генерации и перегенерации:
- PNG-сетка сохраняется в `temp/brackets`
- при включённой синхронизации сайт получает обновлённую картинку

Для CS2:
- доступны отдельные настройки форматов раундов
- доступен пул карт от `1` до `10` уникальных карт
- последовательность ban/pick строится динамически от формата матча и размера пула

---

### 8.6 Создание матчей вручную
Администратор может:
- создать отдельный матч
- выбрать турнир
- выбрать первую команду
- выбрать вторую команду
- задать дату
- задать место

Это отдельный сценарий от турнирной сетки.

---

### 8.7 Ввод результатов через админку
Дополнительно к экрану матча в сетке администратор может:
- открыть сценарий ручного ввода результатов
- сохранить общий счёт
- для волейбола сохранить партии
- сохранить персональную статистику игроков

После сохранения:
- обновляются записи матча
- обновляется рейтинг
- запускается синхронизация сайта

---

### 8.8 Управление пользователями
Что умеет администратор:
- открыть список пользователей
- листать пользователей постранично
- искать пользователей
- открывать карточку пользователя
- редактировать имя, фамилию, username, email, город, возраст, Steam и любимые виды спорта
- точечно изменить рейтинг пользователя по конкретному спорту / сезону / формату
- точечно очистить один выбранный рейтинговый bucket пользователя
- менять роль
- банить и разбанивать

Роли:
- `player`
- `captain`
- `admin`

В карточке пользователя доступны:
- личные данные
- любимые виды спорта
- текущая роль
- статус блокировки
- быстрые действия по рейтингу

---

### 8.9 Управление рейтингами
Что умеет администратор:
- работать отдельно с общим и сезонным рейтингом
- выбирать игроков или команды
- выбрать вид спорта
- для CS2 при необходимости открыть форматный рейтинг
- видеть список игроков/команд с текущими очками, отсортированный по убыванию рейтинга
- вручную добавлять и снимать очки
- точечно очищать конкретный рейтинговый bucket из карточки пользователя или команды
- публиковать live-пост рейтинга в канал из админки
- переводить сезонный рейтинг на следующий сезон с подтверждением

После таких действий:
- рейтинг меняется в БД
- при включённой синхронизации сайт обновляется
- live-посты рейтинга в канале автоматически обновляются

Особенности ручной корректировки:
- сезонный рейтинг можно менять не только для активного, но и для архивного сезона
- корректировка сезонных bucket'ов протягивается и в соответствующий общий рейтинг

---

### 8.10 Управление командами
Что умеет администратор:
- открыть список команд
- листать список
- открыть карточку конкретной команды
- редактировать название, город и лимит участников
- менять капитана
- включать и выключать набор, уведомления и режим invite-ссылки
- точечно изменить рейтинг команды по конкретному спорту / сезону / формату
- точечно очистить один выбранный рейтинговый bucket команды
- управлять составом команды
- исключать участника без блокировки
- исключать участника с блокировкой повторного вступления
- снимать блок повторного вступления
- удалить команду

Это отдельный административный канал управления командами, помимо пользовательского.

---

### 8.11 Рассылка
Что умеет администратор:
- начать рассылку
- ввести текст сообщения
- посмотреть превью
- подтвердить отправку
- отменить рассылку

Рассылка идёт по активным пользователям, у которых есть `telegram_id`.

## 9. Уведомления
Файл:
- `utils/notifications.py`

Реализованы уведомления:
- о назначении матча
- об изменении времени или места
- напоминание за 1 час до матча
- сообщение о результате матча
- о завершении регистрации турнира
- административные уведомления о готовности CS2 veto
- административные timeout-уведомления по veto с возможностью тех.поражения

Кому отправляются:
- участникам обеих команд матча

Для результата поддерживаются:
- подробный формат CS2 по картам и статам
- отдельный формат для футбола
- отдельный формат для баскетбола
- отдельный формат для волейбола

В `main.py` работает отдельный `reminder_worker`, который регулярно проверяет матчи, для которых пора отправить напоминание.

Для администраторов и ответственных:
- есть глобальный переключатель турнирных уведомлений
- есть override уведомлений по конкретному турниру
- часть сообщений является tracked-action сообщениями: если один админ уже обработал действие, у остальных уведомление становится неактуальным

## 10. Работа с рейтингом и очками
Основная логика разбросана между:
- `razryad_arena_utils.py`
- `handlers/admin.py`
- `handlers/match_manual.py`
- `utils/rating_service.py`
- `utils/rating_channel_posts.py`

Что уже есть:
- общий и сезонный рейтинг
- рейтинг игроков и команд
- форматные buckets для CS2 (`1x1 / 2x2 / 5x5`)
- автоматическое начисление очков после матчей и турниров
- отдельные реферальные начисления в общий и сезонный общий рейтинг
- точечные ручные корректировки `+/-`
- точечная очистка одного выбранного рейтингового bucket
- переход на следующий сезон без очистки общего рейтинга
- live-посты рейтинга в канале с автообновлением
- экспорт рейтинга для сайта

Отдельные правила начисления:
- командные матчевые очки обновляются после завершения матча
- игроковые турнирные начисления агрегируются по турниру
- победитель тех.победы получает командные очки и игроковые турнирные очки победителя
- реферальные бонусы не меняют форматный рейтинг CS2

## 13. Синхронизация статического сайта
Это не основной смысл README, но эта часть уже является рабочей функциональностью бота, поэтому она должна быть здесь зафиксирована.

Файл:
- `utils/site_sync.py`

Что делает бот:
1. собирает `tournaments.json`
2. собирает `ratings.json`
3. собирает `matches.json`
4. копирует PNG-сетки турниров
5. заливает всё по FTP на хостинг статического сайта

Когда это происходит:
- при старте воркера
- по таймеру
- после ключевых изменений турниров
- после изменения рейтингов
- после генерации и перегенерации сетки
- после сохранения результатов матчей

Live-посты рейтинга в Telegram-канале — это отдельный механизм, он не заменяет выгрузку на сайт.

Временная папка сборки:
- `temp/site_export/assets/data`

PNG-сетки для выгрузки:
- `temp/brackets/bracket_<id>.png`

Файл:
